# RetailPulse — Free Tier Hosting Guide

Stack: **Vercel** (frontend) + **Render Free** (backend & AI service) + **Neon** (PostgreSQL). Total cost: $0.

> ⚠️ Free-tier trade-offs to know before your demo:
> - Render free services **sleep after 15 min idle**; first request takes ~50-60s to wake up.
> - Render free gives each service **512 MB RAM** — the backend fits, the AI service is tight (tensorflow-cpu is already configured to stay lean).
> - The backend degrades gracefully if the AI service is down — forecasts fall back to local heuristics.
> - Keep the AI service running locally during the demo if cloud RAM proves insufficient (`.\scripts\start-ai-service.ps1`), and set `AI_SERVICE_BASE_URL` on Render to your machine via a tunnel — or just demo without cloud ML.

---

## 0. Prerequisites

1. Code pushed to GitHub: `https://github.com/Thotipaccy/retailpulse`
2. Accounts: [render.com](https://render.com), [vercel.com](https://vercel.com), [neon.tech](https://neon.tech) (all have GitHub sign-in)
3. A Gmail App Password for 2FA emails: Google Account → Security → 2-Step Verification → App passwords

## 1. Create the database on Neon

1. New Project → name `retailpulse` → region closest to you (e.g., AWS eu-central-1 / Frankfurt)
2. Open the created database → copy the **Connection string** (pooled). It looks like:
   ```
   postgresql://USER:PASSWORD@ep-xxxx-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require
   ```
3. Convert it to JDBC form (you'll paste this into Render):
   ```
   jdbc:postgresql://ep-xxxx-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require
   ```
   Tables are created automatically on first backend boot (`ddl-auto: update`) and an admin user is seeded from env vars.

## 2. Deploy backend + AI service on Render

1. Render Dashboard → **New → Blueprint** → select your `retailpulse` repo. It reads `render.yaml` and creates two services:
   - `retailpulse-api` (backend, Dockerfile at `./backend`)
   - `retailpulse-ai` (AI service, Dockerfile at `./ai-service`)
2. Fill in the prompted env vars for `retailpulse-api`:

   | Key | Value |
   |---|---|
   | `SPRING_DATASOURCE_URL` | your Neon JDBC URL from step 1 |
   | `SPRING_DATASOURCE_USERNAME` | Neon user |
   | `SPRING_DATASOURCE_PASSWORD` | Neon password |
   | `CORS_ALLOWED_ORIGINS` | `https://<your-vercel-app>.vercel.app` (add after step 3, then redeploy) |
   | `RETAILPULSE_ADMIN_EMAIL` | your email |
   | `RETAILPULSE_ADMIN_PASSWORD` | a strong password |
   | `MAIL_USERNAME` | your gmail address |
   | `MAIL_PASSWORD` | your Gmail **app password** |
   | `ALERT_EMAIL` | where alert emails go |

   `JWT_SECRET` is auto-generated by the blueprint. `AI_SERVICE_BASE_URL` is pre-wired to the ai service URL — adjust after Render assigns the final URL (it's normally exactly `https://retailpulse-ai.onrender.com/ml`).
3. First deploy builds the Maven project inside Docker (~5-8 min). Check logs until you see `Started RetailPulseApplication`.
4. Verify: open `https://retailpulse-api.onrender.com/api/health` → `{"status":"UP",...}`
5. Verify AI: `https://retailpulse-ai.onrender.com/health` → `{"status":"ok","models_loaded":true}`

## 3. Deploy frontend on Vercel

1. Vercel → **Add New → Project** → import `Thotipaccy/retailpulse`
2. Configure:
   - **Root Directory**: `frontend`
   - Framework preset: **Vite** (build `npm run build`, output `dist` — auto-detected)
   - Environment variable:
     | Key | Value |
     |---|---|
     | `VITE_API_BASE_URL` | `https://retailpulse-api.onrender.com/api` |
3. Deploy → you get `https://<app>.vercel.app`
4. Go back to Render → `retailpulse-api` → Environment → set
   `CORS_ALLOWED_ORIGINS=https://<app>.vercel.app` → **Save & Deploy**
5. Login with your admin credentials (2FA code arrives by email).

## 4. Optional: custom domain
- Vercel: Settings → Domains → add domain, update `CORS_ALLOWED_ORIGINS` accordingly.

## 5. Keeping services warm (demo day trick)
Free instances sleep. Before presenting, hit these once (or use [cron-job.org](https://cron-job.org) every 10 min):
```
curl https://retailpulse-api.onrender.com/api/health
curl https://retailpulse-ai.onrender.com/health
```

## Local full-stack test with Docker

```bash
docker compose up --build
```
- Frontend: http://localhost:3000 (nginx proxies /api → backend)
- Backend: http://localhost:8080/api · AI: http://localhost:8000/docs
- Admin: `admin@retailpulse.local` / `admin12345` — OTP printed in backend logs (`LOG_OTP_TO_CONSOLE=true`)

## Retraining models
Training reads Postgres directly and is CPU/RAM-heavy — run it locally against Neon instead of on Render:
```powershell
cd ai-service
$env:DB_HOST="ep-xxx...neon.tech"; $env:DB_NAME="neondb"; ...
python train\train_all.py
git add models/saved && git commit && git push   # Render redeploys with new artifacts
```

## What was fixed before hosting (security hardening)
- DB dumps, generated reports, and real POS exports removed from git tracking; `.gitignore` now blocks them
- No more default secrets: JWT secret, DB password, admin password all required from environment; weak JWT keys now fail startup
- OTP console logging off by default (`LOG_OTP_TO_CONSOLE`)
- CORS origins env-driven (`CORS_ALLOWED_ORIGINS`, comma-separated)
- Login brute-force lockout (5 fails → 15 min) via `LoginRateLimiter`
- Public `/api/health` endpoint for platform health checks

### Known limitations (documented, not blockers for a demo)
- Refresh tokens are stateless (no server-side revocation); 2FA codes are in-memory — both acceptable single-instance; would need Redis/DB-backed store for multi-instance
- Schema management relies on Hibernate `ddl-auto: update`; Flyway is the long-term fix
